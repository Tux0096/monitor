# rum-collector

Приём Core Web Vitals с сайта и мобильного приложения, свёртка в перцентили,
отдача отчётов дашборду.

Порт **3105**, база `monitor_core` (общая с остальными сервисами monitor).

## Почему не среднее

Распределение времени загрузки скошенное: один запрос на 12 секунд ломает
среднее за час. Храним p50/p75/p95. Основной показатель — **p75**, по нему
Google оценивает Core Web Vitals.

## Эндпоинты

| Метод | Путь | Авторизация |
|---|---|---|
| GET | `/health` | — |
| POST | `/rum/v1/vitals` | — (публичный, для браузеров пользователей) |
| GET | `/rum/v1/report` | service secret |
| GET | `/rum/v1/health/ingest` | service secret |
| POST | `/rum/v1/maintenance` | service secret |

`/rum/v1/vitals` всегда отвечает `204`, даже на мусор: клиент использует
`sendBeacon` и ответ не читает, а сообщать наружу о причинах отказа —
подсказывать, как подбирать payload.

## Защита публичного эндпоинта

- CORS по белому списку origin (`RUM_ALLOWED_ORIGINS`)
- rate limit 120 запросов в минуту на IP
- `bodyLimit` 16 КБ
- строгая схема zod, неизвестные метрики отбрасываются
- границы значений: выброс в 10^9 не попадёт в перцентили
- проверка версии контракта (`v`), расхождение копий скрипта видно в логе

## Хранение

- `rum_events` — сырые события, живут `RUM_RAW_RETENTION_DAYS` суток (по умолчанию 14)
- `rum_rollup_hourly` — часовые перцентили, живут постоянно

Свёртка и очистка запускаются внутри процесса раз в 10 минут.
Свёртка идемпотентна: пересчитывает окно целиком.

## Проверка после деплоя

```bash
SECRET=$(grep -oP '^PERFORMANCE_IMPORT_SECRET=\K.*' /opt/monitor/.env.local)

curl -s http://127.0.0.1:3105/health
curl -s -H "x-monitor-import-secret: $SECRET" http://127.0.0.1:3105/rum/v1/health/ingest
```

Если с сайта данные идут, а с приложения нет — origin WebView не попал
в `RUM_ALLOWED_ORIGINS`. Это самая частая причина.
