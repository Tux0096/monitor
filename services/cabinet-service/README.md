# cabinet-service

Личный кабинет сотрудника в Telegram Mini App. Порт **3106**,
таблицы `cab_*` в `monitor_core`.

Реализованы этапы 1–3 промта: каркас, `CRMReader` с двумя источниками,
вход по `initData`, сессии, `GET /me`.

## Что сделано

| | |
|---|---|
| `CRMReader` | интерфейс + `SeedCRMReader` (фикстуры) + `PostgresCRMReader` (боевая CRM) |
| Контрактная проверка | сверка схемы CRM на старте, нехватка колонки — остановка сервиса |
| `verifyInitData` | подпись HMAC, TTL 60 с, сравнение постоянного времени |
| Сессии | access JWT 15 мин, refresh 30 дней с ротацией и гашением цепочки |
| Привязка | по `requestContact`, при несовпадении — `cab_link_request` |
| Модель доступа | §5, две реализации: чистая функция и SQL, сверены тестами |

## Что не сделано (этапы 4–11)

Новости, база знаний, бонусы с пулом промокодов, фото, админ-API,
перенос на боевого бота.

## Переключение источника CRM

Перенос на продукт — смена конфигурации, не правка кода:

```
CRM_SOURCE=seed → postgres
CRM_DSN=<read-only роль>
```

Выше слоя `crm/` ни один модуль не знает, какая реализация активна.

## Изоляция от текущего продукта

- Все таблицы с префиксом `cab_`, пересечений с 18 существующими нет
- CRM читается только на `SELECT`
- Обработчик Telegram-вебхука не тронут: обращения поддержки создаются как раньше
- Отдельный контейнер: падение не задевает web и pm2

Снос кабинета — в `docs/ROLLBACK.md`.
