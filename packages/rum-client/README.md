# RUM-клиент

Сбор Core Web Vitals с сайта и мобильного приложения, отправка на свой коллектор
(`services/rum-collector`).

Файл `rum.js` **копируется в оба репозитория** — сайта и приложения.
Репозитории разные, общей сборки нет, поэтому копии живут независимо.

## Установка

```bash
npm i web-vitals
```

Скопировать `rum.js` в проект и вызвать один раз при старте приложения:

```js
import { initRum } from "./rum.js";

initRum({
  endpoint: "https://it.franchise-fuji.ru/rum/v1/vitals",
  source: "site",              // "site" в репозитории сайта, "app" в репозитории приложения
  appVersion: __APP_VERSION__, // необязательно, но помогает связать деградацию с релизом
  sampleRate: 1,               // 1 = все сессии, 0.2 = каждая пятая
});
```

Вызывать **после** гидратации, не в критическом пути рендера.

## Что собирается

| Метрика | Что означает | Норма p75 |
|---|---|---|
| LCP | отрисовка главного элемента | ≤ 2500 мс |
| INP | задержка отклика на действие | ≤ 200 мс |
| CLS | скачки вёрстки | ≤ 0.1 |
| TTFB | ответ сервера | ≤ 800 мс |
| FCP | первая отрисовка | ≤ 1800 мс |

Дополнительно: платформа (`web` / `android` / `ios`), группа страниц,
тип соединения, версия приложения.

Персональных данных не собирается: ни идентификаторов пользователя,
ни query-параметров, ни содержимого страницы. Числовые сегменты пути
(`/order/12345`) на стороне коллектора схлопываются в `/order/:id`.

## Почему это не сломает сайт

- Вся логика в `try/catch` — исключение наружу не выйдет ни при каких условиях.
- Отправка через `navigator.sendBeacon`: браузер шлёт данные в фоне,
  переход по странице не задерживается.
- Библиотека грузится динамическим `import()` — не блокирует первый рендер.
- Ничего не тянется со сторонних CDN.
- Коллектор недоступен → клиент молчит, приложение работает.
- Выключается: не вызывать `initRum`, либо `sampleRate: 0`.

## Версия контракта

`PAYLOAD_VERSION` в начале файла. Коллектор принимает только известную версию,
остальное пишет в лог как `version:N`. Если правите `rum.js` — обновите обе копии
и поднимите версию, иначе расхождение проявится потерей данных без явной ошибки.

## Проверка, что дошло

```bash
curl -s -H "x-monitor-import-secret: $SECRET" \
  https://it.franchise-fuji.ru/rum/v1/health/ingest
```

Ответ покажет события за 5 минут, час и сутки в разбивке по платформам.
Если с сайта данные идут, а с приложения нет — почти наверняка origin
WebView не попал в `RUM_ALLOWED_ORIGINS` коллектора.
