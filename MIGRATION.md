# Перенос кабинета на боевые данные

Перенос — **смена конфигурации, а не правка кода**. Ни один модуль выше
слоя `crm/` не знает, какая реализация читателя активна.

## 1. Переключить источник CRM

В `/opt/monitor/.env`:

```
CABINET_CRM_SOURCE=postgres
CABINET_CRM_DSN=postgresql://<read-only роль>@<хост>/fuji_new
```

Роль строго `SELECT` на таблицы из §3 промта. Учётные данные из `.env`
продукта не переиспользовать: у кабинета своя, с меньшими правами.

```bash
cd /opt/monitor && docker compose up -d cabinet-service
curl -s http://127.0.0.1:3106/healthz/crm
```

Ответ должен быть `{"source":"postgres","ok":true,"missing":[]}`.
Если чего-то не хватает — сервис **не стартует** и напишет, каких именно
колонок нет. Это намеренно: молча отдавать пустые права нельзя, это
тихая потеря доступа у всех сотрудников сразу.

## 2. Сверить признак увольнения

Единственное расхождение схемы с промтом. В `workers` есть **два** поля:

| Поле | Кто использует |
|---|---|
| `state` | кабинет (`isActive = state === 1`) |
| `dismissal_date` | существующий синк курьеров (`IS NULL`) |

Перед переключением проверить, что они означают одно и то же:

```sql
SELECT state, count(*) FILTER (WHERE dismissal_date IS NULL) AS работают,
       count(*) FILTER (WHERE dismissal_date IS NOT NULL) AS уволены
FROM workers GROUP BY state ORDER BY state;
```

Если `state = 1` не совпадает с `dismissal_date IS NULL` — поправить
`toCard()` в `src/crm/postgres.ts`. Ошибка здесь стоит дорого в обе
стороны: либо уволенный сохраняет доступ к данным, либо работающий
теряет его без объяснений.

## 3. Ротировать токен бота

**Обязательно до открытия доступа сотрудникам.**

Кто знает токен — подделает `initData` с любым `user.id` и войдёт под
любым сотрудником: увидит его телефон, доступы к внешним системам,
материальные ценности и смены. Подпись — единственная граница доверия.

```
BotFather → /revoke → новый токен
```

Обновить `CABINET_BOT_TOKEN` в `/opt/monitor/.env` и `TELEGRAM_BOT_TOKEN`
в `.env.local`, перезапустить `cabinet-service` и `telegram-poller`.

## 4. Кнопка запуска в боте

```
BotFather → /newapp → выбрать бота
URL: https://it.franchise-fuji.ru/cabinet
BotFather → /mybots → Bot Settings → Menu Button → указать тот же URL
```

Поддержка на этом боте продолжает работать: Mini App сообщений в чат
не отправляет, обработчик вебхука не менялся.

## 5. Синхронизация справочников

```bash
curl -s -X POST -H "x-monitor-import-secret: $SECRET" \
  http://127.0.0.1:3106/admin/refs/sync
```

Заполняет `cab_ref_post`, `cab_ref_department`, `cab_ref_company` —
из них админка выбирает должности и точки при настройке аудиторий.

## 6. Проверка после переноса

```bash
curl -s http://127.0.0.1:3106/healthz/crm     # ok: true, missing: []
```

Затем открыть кабинет из бота под действующим сотрудником и убедиться,
что карточка показывает его настоящие данные, а не фикстуру.

Отдельно проверить уволенного: он должен получить `403 worker_inactive`,
а не карточку.

## Откат

```
CABINET_CRM_SOURCE=seed
docker compose up -d cabinet-service
```

Кабинет вернётся на фикстуры. Данные сотрудников в `cab_*` при этом
останутся — там только `worker_id`, персональных данных кабинет не хранит.

Полный снос — в `docs/ROLLBACK.md`.
